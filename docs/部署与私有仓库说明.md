# 部署说明（GitHub Pages）

给维护者看的部署 readiness 摘要。仓库已面向 **公开** Pages 发布。

## 静态导出

- `next.config.ts`：`output: "export"`，`images.unoptimized: true`，`trailingSlash: true`。
- 设 `GITHUB_PAGES=true` 时：`basePath` / `assetPrefix` = `/china-travel-atlas`（与仓库名一致）。
- 本地 Pages 构建：`npm run build:pages` → 产物在 `out/`。

## GitHub Pages（公开仓）

- 工作流：`.github/workflows/deploy-pages.yml`（`main` 推送后 build → `upload-pages-artifact` → `deploy-pages`）。
- 预计站点：https://lanking520.github.io/china-travel-atlas/
- **Settings → Pages → Source** 选 **GitHub Actions**（首次可能需点一次确认；之后由 workflow 部署）。
- 公开仓库在免费账户上即可使用 GitHub Pages。若曾是私有仓，Pages 曾需要 Pro；公开后一般可直接用。

## 离线 zip / Release / Service Worker

| 项 | 预期 |
|----|------|
| 本地打包 | `npm run pack:offline` → 根目录 `china-travel-atlas-offline.zip` |
| CI Release | 工作流打 zip，并以标签 `offline-latest` 发到 Releases（需 `contents: write`） |
| 给父母用 | 见 [`docs/离线打开说明.md`](./离线打开说明.md) |
| `public/sw.js` | 同域 cache-first 壳页；不缓存外链图/地图 |
| PWA | 生产环境注册 `${basePath}/sw.js` |

## 建议用法

1. 把 Pages 链接发给家人（微信收藏 / 加到主屏幕）。
2. 信号不好时用 Releases 里的离线 zip。
