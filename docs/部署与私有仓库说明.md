# 部署与私有仓库说明

给维护者看的部署 readiness 摘要。**不要**为了上线把本仓库改成公开。

## 静态导出

- `next.config.ts`：`output: "export"`，`images.unoptimized: true`，`trailingSlash: true`。
- 设 `GITHUB_PAGES=true` 时：`basePath` / `assetPrefix` = `/china-travel-atlas`（与仓库名一致）。
- 本地 Pages 构建：`npm run build:pages` → 产物在 `out/`。

静态站本身可部署到任意静态宿主（Pages、对象存储+CDN 等）。

## GitHub Pages 与私有仓库

- 工作流：`.github/workflows/deploy-pages.yml`（`main` 推送后 build → 上传 Pages artifact → deploy）。
- **私有仓库**启用 GitHub Pages 通常需要 **GitHub Pro / Team / Enterprise**（或组织付费套餐）。免费私有仓常见现象：Settings → Pages 未开通，或 Actions 报 `Creating Pages deployment failed` / `Not Found`（API 查 Pages 也是 404）。
- 即使开通，私有站访问往往仍需登录有权限的 GitHub 账号，不适合直接发给父母当「公开链接」。
- **结论**：保持仓库私有；需要在线链接时另选可公开的静态宿主，或只用下方离线包。不要改仓库可见性。

## 离线 zip / Release / Service Worker

| 项 | 预期 |
|----|------|
| 本地打包 | `npm run pack:offline` → 根目录 `china-travel-atlas-offline.zip`（含 `out/` + `离线打开说明.md`） |
| CI Release | 工作流在构建后打 zip，并以标签 `offline-latest` 发布到 Releases（需 `contents: write`） |
| 给父母用 | 见 [`docs/离线打开说明.md`](./离线打开说明.md)：解压后用本地 HTTP 服务打开，勿依赖裸 `file://` |
| `public/sw.js` | 同域 cache-first 预缓存壳页（首页/about/overview/manifest/图标）；**不**缓存 Unsplash/外链地图 |
| PWA | 生产环境由 `PwaRegister` 注册 `${basePath}/sw.js`；有网时先浏览几页再离线看文字更稳 |

离线时以路线文字、预算、须知为准；外链配图与地图可能空白。

## 建议用法（私有仓）

1. 本地或 CI 产出 `china-travel-atlas-offline.zip`，通过 Releases / 网盘发给家人。
2. 需要固定 URL 时，用其他静态托管挂 `out/`，**不必**公开本 GitHub 仓库。
3. 勿为 Pages 单独把仓库改 public。
