# 调研流程：多源发现 → shortlist → 立项 → 精准规划 →（可选）社区复核 → 入库

**小红书不再作为发现源头。** 发现层以公开可引用平台为主；小红书仅作已立项路线的可选复核。

## 总览

```mermaid
flowchart LR
  discover[1 多源发现] --> shortlist[2 Shortlist]
  shortlist --> project[3 立项]
  project --> plan[4 精准规划]
  plan --> review[5 可选社区复核]
  review --> ingest[6 入库]
```

---

### 1. 多源发现（主通道）

| 来源 | 用途 | 输出 |
|------|------|------|
| Wikivoyage（中文） | 城市/省概况、交通、季节 | `research/notes/multi-discovery/<province>.md` |
| 文旅官网 / 景区官网 | 预约、门票、开放 | 同上，sources 标明 official |
| 携程游记 / 马蜂窝 / 穷游 | 行程骨架、天数参考 | 只摘标题+链接+改写要点，禁止整篇搬运 |
| 知乎高赞行程（可选） | 补充争议点/避坑 | 同上 |

词表与清单：[`research/queries-multi.json`](../queries-multi.json)  
汇总脚本：`npm run research:multi-status`  
手工补料目录：`research/raw/multi-manual/`（你可丢 md/csv，再 ingest）

**不再要求** 31 省小红书 discover 摘要齐全才能立项。

### 地级市深挖（增强层）

省摘要不够细、路线 stops 过薄时：按 [`prefecture-depth/README.md`](./prefecture-depth/README.md) 对地级市下属县/区建表并 enrich 路线。队列见 [`prefecture-depth/backlog.md`](./prefecture-depth/backlog.md)。**不要一次声称全国地级市覆盖。**

### 2. Shortlist

[`route-shortlist.md`](./route-shortlist.md)  
门槛不变：北京飞/高铁、健康约 60、日驾优先 ≤5h、电梯房、非特种兵；高原边境写适应与证件；线末可回京。  
**依据** 列须能追溯到多源摘要或官网链接。

### 3. 立项 / 4. 精准规划

同前：patches + `route-provinces` + `route-details`；按大区拆文件便于 fanout。

### 5. 可选社区复核（含小红书）

- 仅对已立项 id：`research/queries.json` → 慢速 MCP / 或你粘贴的笔记标题  
- `npm run research:xhs-apply` 仍可用，但是 **增强项**，不是发现门禁  
- 发现层小红书 keep-alive **默认停用**

### 6. 入库与验收

预览省钻取；`ux:plan`；clean-context 验收看「多源摘要覆盖」而非 XHS digest 数。

## 队列对照

| 队列 | 优先级 | 脚本 |
|------|--------|------|
| 多源发现 | **P0** | 手工/Agent 写 `multi-discovery/`；`research:multi-status` |
| 路线精准规划 | P0 | 内容 patch + details |
| 小红书复核 | P2 可选 | `research:xhs-*` |
